# LMNL data directory

For safekeeping, LMNL sawtooth syntax variants of the Iliad are saved here:

## Strategy

Over the long term:

- Pipelines produce, correct and enhance public data (PerseusDL or other) to produce modified versions suitable for reuse and propagation.

- Handmade LMNL data provides a benchmark of 'intended' markup

- A correction/amelioration pipeline can produce LMNL matching the handmade data from the production pipeline, reproducibly

- This pipeline, when complete, will also serve to record all changes

- Meanwhile, LMNL data of known (if variable) qualify is always available:

  - Use data in `edited` if available
  - If not yet, run the production pipeline and make do with data written to the 'generated' folders
  - Improve data in `edited` any time
  - Never write data into `generated` except via the production pipeline(s)
- Gradually improve production pipeline so `generated/enhanced` matches `edited`
- Develop and document the rules set including whitespace and tag-order related rules

## Files in this folder

### Generated programmatically

These files are *not committed* to the repository but can be regenerated by running the pipeline ../../../run/PRODUCE-LMNL-ILIAD.xpl.



- [PerseusDL_src](./generated/PerseusDL_src/) - serializing directly from distributed source data (TEI XML)

- [enhanced](./generated/enhanced/) - the same data, except with some modifications and improvements.

### Edited by hand

[edited](./edited/) - more enhancements, these done by hand - includes MYTHOI markup.

How to edit LMNL tagging? An XML IDE doesn't give much help. But a plain text editor works well enough, with care. Just be sure you maintain everything in Unicode.

The Laminator submodule repository offers a little support for editing LMNL syntax in TextPad, the Windows text editor for Windows.

## MYTHOI tagging

Ranges marking the text for phenomena, properties or relations not given in the text itself can now be marked even when they overlap and despite any schema.

This makes *exploratory markup* viable and rewarding in ways the XML feature set frustrates. A document can be tagged and then a schema can be derived, rather than having to codify the markup so early.

Tags in this tag set atm include `scene`, `speech`, `tale` (for nested narrative) and others.
